# 乡创引擎 · 农产品卖货演示

当前版本采用 **AI 提前创作完整营销文案，前端读取整稿** 的 Mock 方式。小红书、朋友圈、社群分别写成整篇，浏览器不拼接营销段落，也不替换成稿中的商品名称、价格或交付信息。未接在线模型。

## 启动与验证

使用 Node.js 22.6+（建议 24）和 npm：

```sh
npm install
npm run dev
npm test
npm run build
```

构建产物位于 `dist/`。静态部署需将六个页面路由回退到 `index.html`。本轮未部署上线。

## 60 秒卖货故事动画

首页点击「观看陈叔卖货演示」，或在任一页面顶部点击「动画演示」。这是独立的全屏展示，不自动填写或覆盖当前产品。八幕依次为：陈叔的贡柑 → 卖货前的问题 → 上传照片与填写资料 → 选择交付与确认生成 → AI Agent 分工 → 原图与宣传成果 → 小红书 / 朋友圈预览 → 客户模拟回复。

- 使用 `motion/react`，单一 60 秒时间轴驱动照片推进、文字揭示、扫描遮罩、成品卡展开和手机预览；暂停会同时停止所有镜头和图卡运动。
- 填表幕复用真实页面的三步结构和字段名称，展示整体 / 细节照片选入、名称 / 类别 / 产地 / 称呼填写、补充数量与上市时间、规格售价、配送方式下拉、自提范围 / 运费 / 交付时间 / 售后选项、确认和点击生成。光标、点击提示、输入文字和下拉菜单都跟随同一播放进度，暂停与回退同步。小屏里表单内容和 Agent 卡片会跟随播放进度滚动，下一步 / 生成按钮固定可见；暂停后也可自行滚动阅读。
- 表单演示与实际草稿隔离；演示里的「下一步」「看规格与交付」「看确认与生成」只跳转片内画面，不自动填写真实表单。
- Agent 幕展示商品整理、文案创作、视觉素材、检查与客服四类分工，分别说明输入和输出。后续成果画面也注明对应助手。这里是协作流程模拟，当前仍读取本地预制成稿和图片，并使用已有规则与模拟客服，不连接在线模型。
- 支持播放、暂停、拖动进度、重播、上一幕 / 下一幕和章节跳转。手动跳转暂停播放并呈现该幕完整构图。键盘空格控制播放（画面获得焦点时），左右键切换章节，Escape 返回工作台。
- 渠道预览内可切换小红书与朋友圈，下载对应静态 PNG、复制现有完整成稿，打开手动发布步骤。小红书步骤中可另外下载商品介绍卡。
- 开始前读取两张指定照片和四张成品，失败提供重试；切到后台自动暂停。系统启用“减少动态效果”时默认静态分幕查看，并关闭推近、位移、扫描闪光和卡片旋转。
- 关闭演示保留原有填写、方案与文案。片尾进入陈叔手动流程时，若已有资料，沿用确认切换机制；不会一键填表。
- 桌面和手机使用不同构图，横屏压缩标题和控件间距。动画模块按需加载，原有六个路由和普通产品流程保持不变。

浏览器检查覆盖播放与镜头暂停、完整播完停留片尾、进度跳转、两渠道复制、下载文件一致性、发布步骤、图片失败重试、关闭后资料保留、减少动态效果与四种视口。检查不生成截图，不代表真实手机硬件帧率测试。

## 陈叔贡柑的手动演示

1. 首页点击「陈叔贡柑演示」，下载资料包。
2. 手动上传两张指定图片并填写参考商品资料，不提供自动填写。
3. 配送 / 取货方式、交付范围、运费、发货 / 自提时间、售后使用下拉选项；不确定可留待确认。更改交付方式会清空旧交付安排，需重选。
4. 确认后点击生成，显示约 1.2 秒准备进度，读取 AI 预写完整文案与四张静态 PNG。
5. 在卖货方案下载场景图；在素材页下载小红书封面、介绍卡、朋友圈图，编辑并复制完整渠道文案。
6. 进行发布前规则检查，按页面步骤手动发布，勾选行动清单。模拟客服在「可以发布的图文 → 客户咨询 / 模拟客服」中使用。

资料包：`public/demo/citrus/陈叔贡柑演示资料包.zip`。逐项操作说明：`public/demo/citrus/填写说明.md`。

## 完整文案及匹配规则

- `src/mock-copy.json` 保存荔枝、红茶、贡柑三组 AI 预写整稿，每组分别包含小红书标题 / 正文 / 标签、朋友圈、社群、图卡摘要与回复。
- `src/demo-data.json` 是商品参考事实；完整稿只在名称、类别、产地、特点、数量、上市时间、用途、售价、规格及交付资料均匹配时读取。不通过产品 ID 或名称单独猜测。
- 优先渠道只决定展示顺序，不影响匹配；用户本地照片仍保留。普通匹配模式使用 Canvas 排版自己上传的照片。
- 修改价格、规格或其他商品事实后，旧方案标记待更新。更新时若没有对应整稿，就保留准备指导和空白文案编辑区，提示待填写；不把旧文案改几个字段后冒充 AI 新稿。
- 非预设产品仍可上传照片、保存当前资料、查看六步指导、手动编辑文案、使用模拟客服、导出准备方案。空白或规则冲突的文案不可直接复制发布或下载图卡。
- 已编辑的草稿会保留；重新生成前提示替换。AI 原稿不会被编辑操作污染。
- 便于阅读的文案副本：`public/demo/AI预写完整文案.md`。陈叔副本：`public/demo/citrus/固定文案.md`。

## 模拟客服与保存

模拟客服按当前方案快照和关键词组织回复，约 650 毫秒后呈现草稿，支持编辑、复制、清空。它与 AI 预写营销文案属于两条不同的演示路径；没有真实客户消息或在线模型请求。未知价格、优惠、认证和交付事项会提示核实；方案过期时暂停模拟回复，离开页面清空对话。

照片只在当前浏览器页面读取，不上传服务器。信息仅保存在本次会话，刷新或关闭会清空。Markdown 可导出当前商品、已编辑文字、待办和图片资源清单；图片分别下载，导出不包含临时对象地址，也不是可导入的项目备份。

## 检查和边界

36 项自动测试覆盖完整稿原样读取、全部商品事实匹配、无匹配稿的空白编辑、编辑保留、旧快照失效、规则检查、交付选项、模拟客服、图片指纹与尺寸、异步准备和取消。TypeScript 与 Vite 构建通过。按用户偏好未追加截图；动画做了浏览器桌面、手机视口操作检查，未做真实手机硬件测试。

规则检查只覆盖已配置项目，不能核验证书真伪或所有语义。照片不用于推断品种、品质和认证。人工确认后由用户自行发布；没有自动登录、订单、支付或物流。AI 文案的实际阅读与成交效果尚未验证。

中文图片缺字修复：静态图卡已更换中文字体并重新导出；离线导出先逐字检查字体覆盖。网页预览与下载共用版本标识，下载重新校验缓存。商品照片保持原图。已直接检查三张 PNG 的中文显示，未进行页面截图检验。
